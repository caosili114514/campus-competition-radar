# 已知限制与使用边界

> **当前状态（重要）**：GitHub Pages 站点已手动部署成功，地址为 <https://caosili114514.github.io/campus-competition-radar/>，线上当前为明确标记的演示数据。部署工作流已实际运行成功，但每日数据更新工作流尚未首次执行；六个候选来源已启用但均未人工核验，因此不能把后续自动记录当作官方确认。

## 1. 纯静态架构限制

- 没有真正的多人账户、登录、会话或用户资料系统。所有用户看到的是同一份公开静态文件。
- 没有跨设备同步。收藏、进度、备注等只保存在当前浏览器、当前站点的 `localStorage` 中；换浏览器、换设备、清理站点数据或使用隐私模式后不会保留。
- 没有服务端权限控制。前端代码、`docs/data/` 数据以及任何被打包到 Pages 的内容都可被访问和下载，不能把秘密、访问令牌或敏感信息放进静态站点。
- 不能在客户端执行需要服务器凭据的采集、代理、数据库或定时任务。采集与数据更新依赖 GitHub Actions 和提交到仓库的数据文件。
- 若要实现登录、跨设备同步、角色权限、审计或多用户写入，必须引入独立后端与认证服务，这超出了当前纯静态站点的范围。

## 2. 信息抓取与来源范围

- 采集器只应处理公开 HTML 列表、RSS/Atom 和 JSON feed 等可公开访问的来源，不能保证覆盖所有学校、所有竞赛或所有报名批次。
- 微信公众号文章不能在浏览器端或采集器中批量抓取；不得绕过登录、验证码、访问控制或反爬机制。手动公众号公开链接只能作为人工核验入口，失败时应进入待核验队列，而不是假装抓取成功。
- 来源可能变更页面结构、限流、返回 403/404、超时或只返回 JavaScript 动态内容，采集器无法保证每次都能解析。
- 使用来源时必须遵守站点 robots 规则、服务条款、版权要求和合理请求频率；当前仓库把六个候选来源设为 `enabled: true`、`verified: false`。启用只表示允许低频访问，不表示来源或许可已经核验。
- 若所有已启用来源都不可用或过滤后没有记录，采集器可以成功运行但只产出空记录或明确的未完成状态；这不代表赛事数据库完整或经过官方确认。发布保护会保留现有演示或历史数据。

## 3. 数据质量与时效性

- 自动抽取的标题、主办方、类别、级别、地区、报名起止时间、对象、团队人数和作品要求可能不完整或有误；无法确认的字段应保持 `null`，界面显示为待确认，不能推断成确定事实。
- 信息源未验证时不能标注为官方确认。`verified: false` 表示来源或记录还需要人工核验；即使链接返回 HTTP 200，也不等于报名已开放、赛事仍有效或内容已被官方认可。
- 截止状态和剩余天数由当前时间和已解析字段动态计算；时区、跨日、截止日期缺失或来源临时下线都会造成显示差异。
- 数据可能滞后于主办方最新通知。报名、提交或缴费前必须回到主办方原始页面复核。
- 演示数据必须显示演示横幅和逐条演示标识；不能把 `data_mode=demo`、空结果或未核验记录描述为真实、完整、官方的赛事清单。

## 4. GitHub Actions 定时任务

- 定时规则使用 UTC。当前配置为每天 UTC 18:17，即北京时间次日 02:17（UTC+8）。
- GitHub Actions 的 `schedule` 是尽力而为，可能延迟数分钟、延迟更久或在平台繁忙时跳过；不能将其视为实时数据或严格 SLA。
- 计划工作流通常要求位于默认分支并保持 Actions 启用；仓库长期无活动、权限变更或 Actions 配置调整也可能影响运行。具体政策以 GitHub 当前官方文档为准。
- 需要立刻更新时，应使用 `workflow_dispatch` 手动运行；失败后不要依靠 force push 修复。
- 数据提交使用仓库 `GITHUB_TOKEN`。这类提交通常不会再次触发 `push` 工作流，因此部署工作流同时监听数据更新工作流的完成事件；该自动链路仍需在真实仓库中首次验证。

## 5. GitHub Free、Actions 与 Pages 额度

免费政策和额度会调整，以下只描述一般原则，**以 GitHub 当前 Free 套餐官方文档为准**：

- 公共仓库通常可以使用免费的 GitHub Actions 标准托管 runner 和 GitHub Pages；私有仓库的 Actions 使用通常受月度分钟数、存储额度或组织策略限制。
- GitHub Pages 有站点大小、构建、带宽、发布频率或合理使用方面的限制。公开项目也可能受账户级或平台级软限制，不应把 Pages 当作大流量生产 CDN。
- 私有仓库是否启用 Pages、是否包含 Actions 分钟数以及具体额度，取决于当前套餐和账户设置，本文不给出固定数字。
- 第三方信息源、API 或抓取目标可能有自己的限流和费用；GitHub 免费额度不覆盖这些外部限制。
- 需要最新细节时，请查阅 GitHub Actions 计费、GitHub Pages 限制和 GitHub Free 计划官方页面，并检查仓库 Settings 中的实际用量与权限。

## 6. 浏览器、CORS 与网络限制

- 没有浏览器端 CORS 后端、代理服务或边缘函数。前端只能直接 `fetch` 同站点静态文件或明确允许跨域的资源；第三方接口如果未配置 CORS，浏览器会拦截请求。
- 纯前端无法绕开 CORS、Cloudflare、登录墙、验证码、Cookie 限制或目标站点的反爬策略，也不应尝试绕过。
- 浏览器端不能运行 Python 采集器。数据更新必须在 GitHub Actions 的 Python 环境中完成，并将结果写入 `docs/data/` 后发布。
- GitHub Pages、DNS、网络运营商或访问者所在网络都可能造成暂时不可达；本静态项目不提供可用性 SLA。
- 深层链接使用 hash 路由，项目子路径部署时依赖相对路径；如果手工修改资源路径或搬移到不兼容的托管方式，可能出现 404。

## 7. 隐私、安全与法律边界

- 收藏、进度和备注保存在浏览器本地，没有服务端加密、备份或访问审计；在共享电脑上使用时应自行清理浏览器数据。
- 站点不收集账户密码，但静态页面可能被第三方托管平台记录基础访问日志；不要在前端填入身份证号、手机号、报名凭证或其他敏感个人信息。
- 抓取或转载内容必须尊重来源版权、服务条款和 robots.txt 规则，并保留原始链接与来源说明；不能把第三方内容包装成官方发布。
- 主办方名称、Logo 或赛事信息可能涉及商标和版权；公开展示前应确认使用权限。
- 需要身份认证、授权、付费或隐私合规的功能必须另行设计后端和数据治理流程，静态站点不能提供这些保证。

## 8. 明确不在当前范围的能力

- 真正的多用户账号、服务端登录态、跨设备同步和服务端权限控制。
- 公众号批量抓取、绕过验证码/登录/反爬、实时监控所有报名入口。
- 对赛事真实性、报名开放状态或官方认证作出自动保证。
- 大流量生产级托管、服务端 API 代理、数据库、邮件/短信通知和高可用 SLA。
